## 🔄 How to Use This Folder

### For Updates:
1. **Add new information** to the appropriate subfolder
2. **Update the master documents** in `05-Master-Documents/`
3. **Mark outdated information** with `[DEPRECATED - DATE]` tag
4. **Keep version history** - don't delete, just mark as superseded

### For Reference:
1. **Start with `05-Master-Documents/`** for quick overview
2. **Drill down** to specific folders for detailed info
3. **Check date stamps** to ensure you're using latest data

### For Feeding to AI/Analysis:
1. Use **master documents** for comprehensive context
2. Use **specific folder docs** for focused analysis
3. Combine **client + product + strategy** for complete picture

## 🔍 What's Different from Original Folders?

**Old Structure Problems:**
- Information scattered across multiple files
- Related info split (e.g., client data in 3 different files)
- Duplicated content
- Hard to find latest version
- Mixed topics in single files

**New Structure Benefits:**
- ✅ Related information grouped together
- ✅ Clear separation of concerns (client vs. product vs. strategy)
- ✅ Easy to update single topic without affecting others
- ✅ Quick navigation to what you need
- ✅ Master documents for comprehensive view
- ✅ Version control and update tracking

## 📝 Maintenance Guidelines

### When to Update:
- ✅ After every client interaction (add to Client-History)
- ✅ When product features change (update Product-Specifications)
- ✅ When strategy evolves (update Playbook-Master)
- ✅ When team situation changes (update Our-BATNA, Costs-Financials)
- ✅ After negotiation meetings (capture learnings)

### How to Update:
1. Edit the specific file in its subfolder
2. Add `[UPDATED YYYY-MM-DD]` tag to changed sections
3. Update the `UPDATE-LOG.md` with summary of changes
4. If major change, update `MASTER-CONTEXT.md` as well

### What NOT to Do:
- ❌ Don't delete old information (mark as deprecated instead)
- ❌ Don't create new files without updating this README
- ❌ Don't duplicate information across multiple files
- ❌ Don't update one place without checking if others need updating
