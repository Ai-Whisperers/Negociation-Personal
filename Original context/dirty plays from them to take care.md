**Manual Operativo de Negociación — Proyecto Software (v1.1)**
*(basado en la transcripción del 16-10-2025)*

---

### 🧭 1. Núcleo Estratégico

* **Objetivo:** fijar un precio justo, defendible y escalable.
* **Regla:** *nunca negociar sin costo calculado* (horas, tokens, storage, soporte).
* **Principio:** mostrar valor tangible → “lo que entregamos procesa datos reales, no promesas”.

---

### ⚙️ 2. Procedimiento Base

1. **Pre-negociación**

   * Preparar documentación técnica + presupuestaria.
   * Definir umbral mínimo aceptable (coste total × 1.4).
   * Tener lista una tabla de insumos: horas, infraestructura, librerías, storage (GB), API tokens.
2. **Negociación**

   * Exponer beneficios con métricas (velocidad, precisión, automatización).
   * Mencionar comparativos del mercado (“empresas grandes pagan 2-3× esto”).
   * Si piden “rebaja”, reducir *alcance*, no *precio*.
3. **Post-acuerdo**

   * Formalizar en documento: entrega, soporte, límites de uso, derechos de mejora.
   * Guardar trazabilidad de todo intercambio (para defensa contractual).

---

### 🔄 3. Planes Alternativos (Dirty-Play Protocol)

| Escenario                                  | Señal                                  | Contramedida                                                      |
| ------------------------------------------ | -------------------------------------- | ----------------------------------------------------------------- |
| 1️⃣ Intentan *demorar pagos*               | Excusas administrativas                | Cláusula: acceso suspendido si > 10 días mora.                    |
| 2️⃣ Quieren *copiar el producto*           | Solicitan código o “instalación local” | Entregar **black-box build** + licencia limitada, sin core logic. |
| 3️⃣ *Sub-cotizan* o traen “otro proveedor” | Dicen “el otro lo hace por menos”      | Mostrar costos desglosados y cerrar con ROI por token.            |
| 4️⃣ *Filtran datos o modelo*               | Solicitan muestras de dataset o modelo | Solo demos anonimizadas, nunca código fuente ni pesos reales.     |
| 5️⃣ *Engaño contractual* (firma ambigua)   | Cambian cláusulas último momento       | Releer línea por línea, exigir contrafirma o suspender trato.     |

---

### 🧱 4. Protección Operativa

* Usar **NDA + SLA dual** (confidencialidad + niveles de servicio).
* Implementar versión compilada y registro interno de checksum/hash.
* Registrar logs de uso → prueba de propiedad.
* Mantener backups cifrados fuera del entorno del cliente.

---

### 🚀 5. Modo Overkill (si hay intento de apropiación)

* Replegar build remoto → cortar acceso API.
* Publicar versión “Community” reducida → proteger IP y mantener reputación.
* Ofrecer “consultoría de continuidad” (pago por hora) para mantener control simbólico.
* Registrar patente o “software declaration of authorship”.

---

**Resultado esperado:**
Control, rentabilidad y protección de propiedad intelectual ≥ 0.9 nivel de seguridad.
**Métrica de éxito:** ninguna concesión sin retorno ≥ 3× coste marginal.
